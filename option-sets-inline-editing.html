PrototypeRows save as one write only when you press Enter or leave the row. Esc reverts.

When a row saves

  • Press Enter in any cell of the row.
  • Focus leaves the row: click anywhere outside it, or Tab/Shift+Tab past its first or last cell.
  • Moving between cells in the same row never saves. There's no timer or auto-save.
  • Esc reverts the row to its last saved values and sends nothing.

What's sent

  • One write per row with the whole row: { name, extraCost, sellTax }. No per-field patches.
  • Nothing is sent if the values match the last saved values.
  • If a save for the same values is still in progress, it isn't sent again (e.g. Enter, then leaving the row).
  • Responses that arrive out of order don't overwrite a newer saved state.
  • Deleting a row (bin icon) sends a delete straight away.

New modifiers

  • "Add modifier" adds an unsaved row and focuses its name. Only one unsaved row per option set at a time.
  • It's created on the first save, which needs a name.
  • A blank new row is removed when you leave it. Esc or the bin icon removes it without a write.

Validation (blocks the write)

  • Name is required.
  • Names must be unique within the option set, ignoring case and extra spaces ("chili " = "Chili"). The same name is allowed in different option sets.
  • Checked on save, not while typing. The error clears as soon as the name is valid. Typed values are kept.
  • If a clash is fixed by renaming or deleting the other modifier, the blocked row saves when that change is saved.
  • Client-side only in the prototype. The API must enforce uniqueness too.

Feedback

  • One status per option set, next to "Used by": "Saving…", then "Saved" (shown 2s, then fades) or "Couldn't save".
  • Errors appear below the table in row order. The row gets a red bar.
  • Option sets used by more than one product show an Undo toast for 6s after each successful save.
  • Extra cost drops non-numeric characters as you type and is formatted to 2 decimals when you leave the cell. That isn't a save.

Failures

  • The simulated request takes 900ms. With "Simulate save failure" on, every write fails.
  • Typed values are kept and a Retry link is shown.
  • Leaving the row doesn't resend a save that just failed. Enter and Retry do. Esc discards the change.

Name suggestions

  • Typing in a Name cell lists up to 6 saved modifiers from all option sets whose name contains the text (case-insensitive). Names that start with it are listed first.
  • Each shows its price, tax and option set(s). Names already in this option set are shown but can't be picked.
  • Picking one (click, or ↓/↑ then Enter) copies its name, price and tax into the row. That isn't a save; the row still saves on Enter or leaving it.
  • Esc closes the list without reverting. Enter with nothing highlighted saves what you typed.

Not covered by this prototype

Drag to reorder, Create / Duplicate / Delete option set, select all, search and the "Used by" counts are mock-ups only. They don't produce writes and aren't part of this spec. The Writes panel shows every request the page would make.
